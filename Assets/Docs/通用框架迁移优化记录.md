# 通用框架迁移优化记录

## 文档说明

本文档记录从 `NewGameFramework`（下文简称 NGF）迁移到 `GameFramework`（下文简称 GF）的通用框架模块，以及迁移过程中已经完成的结构调整、实现替换和兼容性优化。

- 记录依据：会话《框架迁移优化》及 GF 当前实际源码
- 记录原则：只记录已经迁移并落地的内容
- 当前记录范围：`BaseSingleton`、`ApplicationTool`、`Logger`、`PlayerPrefsSetting`、`EventSystem`、`UI UIView`、`StateMachine`
- 源码目录：`Assets/C#Scripts/Framework`

## 已完成迁移顺序

| 顺序 | 模块 | 迁移状态 | 顺序原因 |
| --- | --- | --- | --- |
| 1 | `BaseSingleton` | 已完成 | 提供普通 C# 单例和 MonoBehaviour 单例，是 `Logger` 等管理类的基础依赖 |
| 2 | `ApplicationTool` | 已完成 | 无框架内依赖，可在单例基础层完成后独立迁移 |
| 3 | `Logger` | 已完成 | 继承 `Singleton<Logger>`，因此在单例基类之后迁移 |
| 4 | `PlayerPrefsSetting` | 已完成 | 使用 `Logger` 输出关键操作日志，因此在日志模块之后迁移 |
| 5 | `EventSystem` | 已完成 | `EventCenter` 继承 `Singleton<EventCenter>`；依赖单例基础层，但不依赖其他业务模块 |
| 6 | `UI UIView` | 第二阶段已完成 | 在 UI 运行环境和面板生命周期基础上，完成稳定的 UI 元素绑定与代码生成工具 |
| 7 | `StateMachine` | 已完成 | 纯 C# 独立模块，为后续 GuideSystem 等流程型业务提供枚举强类型状态管理 |

## 1. BaseSingleton

### 相关文件

- `Assets/C#Scripts/Framework/BaseSingleton.cs`

### 模块职责

该文件提供两类单例基础设施：

- `Singleton<T>`：不依赖 Unity 生命周期的普通 C# 单例。
- `SingletonMono<T>`：依赖 Unity 生命周期、可挂载到 GameObject 的 MonoBehaviour 单例。
- `SingletonRuntimeState`：记录应用退出状态，避免退出阶段重新创建 MonoBehaviour 单例。

### 普通 C# 单例的改动

#### 1. 增加线程安全保护

NGF 使用空合并赋值创建实例：

```csharp
instance ??= new T();
```

该实现没有同步保护。GF 改为使用私有同步对象，并在访问或查询实例时加锁，避免多个线程首次访问时重复创建实例。

#### 2. 收紧泛型约束

GF 使用以下约束：

```csharp
where T : Singleton<T>, new()
```

派生类型必须以自身作为泛型参数，减少错误继承和错误类型组合。

#### 3. 增加不创建实例的查询接口

新增：

```csharp
SingletonType.HasInstance
SingletonType.TryGetInstance(out SingletonType value)
```

这两个接口只查询已有实例，不会像访问 `Instance` 一样触发创建，适用于退出、清理和可选服务检查。

#### 4. 优化清理流程

NGF 的 `Clear()` 通过 `Instance = null` 清理，存在为了清理而先访问或创建实例的风险。

GF 的 `Clear()` 直接读取静态字段并清空引用：

- 未创建实例时不会创建新实例。
- 在锁内交换静态引用。
- 在锁外调用 `OnRelease()`，避免释放逻辑长时间占用单例锁。

同时新增：

```csharp
protected virtual void OnRelease()
```

派生类可以在实例被清除前释放事件、缓存或其他资源。

#### 5. 保留显式初始化方式

`OnInit()` 仍由项目启动流程显式调用，首次访问 `Instance` 时不会自动初始化。

这样可以兼容 NGF 的初始化习惯，并避免实例创建与业务初始化被隐式绑定。

### MonoBehaviour 单例的改动

#### 1. 优先复用场景已有对象

NGF 在静态引用为空时直接创建新的 GameObject。

GF 会先执行：

```csharp
Object.FindAnyObjectByType<T>(FindObjectsInactive.Include)
```

因此可以找到并复用场景中已经存在的实例，包括未激活对象，降低重复创建单例的风险。

#### 2. 增加重复实例处理

GF 在 `Awake()` 中检查是否已经存在其他实例：

- 首个实例被保留。
- 后创建的重复实例所在 GameObject 会被销毁。
- Console 会输出重复单例警告。

NGF 只在实例为空时赋值，但不会销毁重复对象，可能出现多个常驻 GameObject 同时运行。

#### 3. 增加类型安全约束

NGF 的约束是：

```csharp
where T : MonoBehaviour
```

GF 改为：

```csharp
where T : SingletonMono<T>
```

同时在 `Awake()` 中再次检查泛型参数是否为自身类型，降低错误声明造成的静态实例类型异常。

#### 4. 避免非运行状态创建对象

GF 在 `Application.isPlaying` 为 `false` 时拒绝自动创建 MonoBehaviour 单例，并返回 `null`。

这可以避免编辑器非播放状态下读取 `Instance` 时污染当前场景。

#### 5. 避免应用退出时重新创建对象

新增 `SingletonRuntimeState`：

- 监听 `Application.quitting`。
- 应用退出后将 `IsQuitting` 设置为 `true`。
- 退出期间访问 `Instance` 时不再创建新 GameObject。
- 使用 `RuntimeInitializeOnLoadMethod(SubsystemRegistration)` 重置状态，兼容关闭 Domain Reload 的编辑器配置。

#### 6. 自动维护静态引用

- 实例创建或被发现后使用 `DontDestroyOnLoad` 跨场景保留。
- 实例销毁时在 `OnDestroy()` 中清除静态引用。
- 增加 `HasInstance` 和 `TryGetInstance()`，查询时不会搜索场景或创建对象。
- 添加 `DisallowMultipleComponent`，阻止在同一 GameObject 上重复添加同类组件。

### 使用约束

派生的 MonoBehaviour 单例如果覆盖 `Awake()` 或 `OnDestroy()`，必须调用基类实现，否则重复实例检查或静态引用清理会失效。

```csharp
protected override void Awake()
{
    base.Awake();
}
```

## 2. ApplicationTool

### 相关文件

- `Assets/C#Scripts/Framework/ApplicationTool.cs`

### 模块职责

为 Unity 应用运行环境、运行平台、网络可达类型和产品信息提供统一的静态访问入口。

### 已完成改动

#### 1. 统一命名空间

NGF 中的类型位于全局命名空间。GF 将其迁入：

```csharp
namespace GameFramework
```

用于减少全局类型污染，并与其他通用框架模块保持一致。

#### 2. 按职责重新组织代码

使用 `region` 将接口划分为：

- `运行环境`
- `网络状态`
- `产品信息`

只调整代码组织，没有引入额外运行时状态或缓存。

#### 3. 保留 Unity API 的轻量封装

以下接口继续直接读取 Unity API：

```csharp
IsPlaying
IsEditor
IsBuildRuntime
CurrentPlatform
InternetReachability
ProductName
GameVersion
CompanyName
```

该工具不缓存这些值，调用时返回 Unity 当前状态。

#### 4. 将网络判断拆为明确属性

新增：

```csharp
IsNetworkReachable
IsLocalAreaNetworkReachable
```

其中：

- `IsNetworkReachable` 只判断 `Application.internetReachability` 是否不为 `NotReachable`。
- `IsLocalAreaNetworkReachable` 只判断 Unity 是否报告 `ReachableViaLocalAreaNetwork`。
- `IsNetworkAvailable()` 保留为方法形式，并转调 `IsNetworkReachable`。

NGF 的 `IsWifiOrWiredConnected()` 已由语义更明确的 `IsLocalAreaNetworkReachable` 替代，当前 GF 源码不再保留旧方法。

#### 5. 修正功能说明

NGF 的部分注释把网络可达类型描述成“有可用网络”或“已连接 Wi-Fi/有线网络”，容易被理解为真实联网检测。

GF 的注释已改为与 Unity API 实际语义一致：

- `Application.isPlaying` 在构建后的 Player 和 Editor 播放模式中都可能为 `true`。
- `Application.internetReachability` 不会主动探测互联网或指定服务器。
- `ReachableViaLocalAreaNetwork` 无法进一步区分 Wi-Fi 与有线网络。
- 网络可达类型不代表目标服务一定可以访问。

### 兼容性说明

旧代码如果调用：

```csharp
ApplicationTool.IsWifiOrWiredConnected()
```

需要改为：

```csharp
ApplicationTool.IsLocalAreaNetworkReachable
```

如果业务需要确认服务器是否可用，应另外执行实际网络请求，不能只依赖本工具的网络可达属性。

## 3. Logger

### 相关文件

- `Assets/C#Scripts/Framework/Logger.cs`

### 模块职责

提供统一格式的信息、警告和错误日志输出，并在不需要日志的正式构建中通过条件编译移除调用。

### 已完成改动

#### 1. 替换运行时堆栈扫描

NGF 每次输出日志都会创建 `StackTrace`、遍历 `StackFrame`，再寻找第一个非 `Logger` 调用者。

GF 改为使用编译器调用方信息：

```csharp
[CallerFilePath]
[CallerMemberName]
```

日志来源不再依赖运行时堆栈扫描，减少日志调用产生的对象和遍历开销。

当前输出格式为：

```text
[源文件名.成员名] 日志内容
```

该来源用于快速识别调用位置，不承诺改变 Unity Console 的双击跳转规则。

#### 2. 调整条件编译策略

NGF 只在定义 `ENABLE_DEBUG_LOG` 时保留日志调用。如果 GF 尚未配置该宏，原样迁移会导致编辑器中的 Logger 调用也被编译器移除。

GF 为每个日志方法设置了以下条件：

```text
UNITY_EDITOR
或 DEVELOPMENT_BUILD
或 ENABLE_DEBUG_LOG
```

满足任意条件时保留调用：

- Unity Editor 中可以直接调试。
- Development Build 中可以保留调试日志。
- 其他构建可以通过显式定义 `ENABLE_DEBUG_LOG` 保留日志。
- 正式非 Development Build 且未定义宏时，日志调用及其参数计算会被编译器移除。

#### 3. 规范日志接口

当前提供：

```csharp
LogInfo(string message, Object context = null, ...)
LogWarning(string message, Object context = null, ...)
LogError(string message, Object context = null, ...)
```

NGF 中拼写错误的 `LogWarring` 已更名为 `LogWarning`，当前 GF 源码不再保留旧拼写接口，旧调用需要同步修改。

#### 4. 增加 Unity 对象上下文

日志接口新增可选的 `UnityEngine.Object context` 参数，并传递给 `Debug.Log`、`Debug.LogWarning` 或 `Debug.LogError`。

调用方可以关联 GameObject、Component 或其他 Unity 对象，便于在 Console 中定位相关对象。

#### 5. 规范运行时开关

NGF 的公共字段：

```csharp
isPublicLog
```

已替换为属性：

```csharp
IsEnabled
```

该属性只控制已经被编译保留的日志是否实际输出，不改变条件编译结果。

#### 6. 收紧类型设计

- `Logger` 迁入 `GameFramework` 命名空间。
- `Logger` 标记为 `sealed`，不再允许无必要的继承。
- 继续继承 `Singleton<Logger>`，使用已迁移的线程安全普通单例基础实现。
- 按“日志开关、日志输出、内部方法”划分代码区域。
- XML 注释已改为描述当前真实行为。

### 使用示例

```csharp
Logger.Instance.LogInfo("初始化完成");
Logger.Instance.LogWarning("资源未找到", gameObject);
Logger.Instance.LogError("配置加载失败");
```

`GameFramework.Logger` 与 `UnityEngine.Logger` 同名。当一个脚本同时使用 `UnityEngine` 和 `GameFramework` 时，建议使用类型别名：

```csharp
using Logger = GameFramework.Logger;
```

### 兼容性说明

- `isPublicLog` 调用需要改为 `IsEnabled`。
- `LogWarring(...)` 调用需要改为 `LogWarning(...)`。
- 使用全局命名空间中 `Logger` 的旧代码，需要引入 `GameFramework` 命名空间或使用类型别名。
- 日志来源由“运行时调用类型全名”变为“源文件名 + 成员名”。

## 4. PlayerPrefsSetting

### 相关文件

- `Assets/C#Scripts/Framework/PlayerPrefsSetting.cs`

### 模块职责

为 Unity `PlayerPrefs` 提供统一的偏好数据读写入口，支持：

- 键存在性检查。
- 单键删除和全部删除。
- `bool`、`int`、`float`、`string` 的读取与写入。
- 显式调用 `Save()` 将已修改的偏好数据写入持久化存储。

该类只封装当前应用的轻量偏好设置，不承担复杂游戏存档职责。

### 已完成改动

#### 1. 从单例管理器改为静态工具

NGF 的类型定义为：

```csharp
public class PlayerPrefsSettingMgr : Singleton<PlayerPrefsSettingMgr>
```

但原类型没有实例字段、缓存或有效生命周期，所有方法都只是转调静态的 `UnityEngine.PlayerPrefs`。

GF 将其改为：

```csharp
public static class PlayerPrefsSetting
```

本次同时完成：

- 移除对 `Singleton<T>` 的无意义继承。
- 移除 `.Instance` 调用层级。
- 不再需要 `OnInit()` 或 `Clear()` 生命周期。
- 类型名移除 `Mgr` 后缀，明确其本质是无状态静态封装而不是管理器实例。
- 迁入 `GameFramework` 命名空间。

#### 2. 修正 Save 返回值语义

NGF 的 `Save()` 在调用 `PlayerPrefs.Save()` 后固定返回 `true`：

```csharp
public bool Save()
{
    PlayerPrefs.Save();
    return true;
}
```

Unity 原接口不提供保存是否成功的返回值，因此这个 `bool` 无法反映真实结果。

GF 将接口改为：

```csharp
public static void Save()
```

保存完成后仍通过 `Logger` 输出操作日志，但不再返回没有依据的成功状态。

#### 3. 统一校验 PlayerPrefs 键

新增内部 `ValidateKey()`，所有需要键名的公开接口都会拒绝：

- `null`
- 空字符串
- 只包含空白字符的字符串

无效键会抛出包含参数名的 `ArgumentException`，避免错误数据继续传递到底层 PlayerPrefs API。

#### 4. 增加字符串值空引用检查

`SetString()` 会单独检查写入值：

```csharp
if (value == null)
{
    throw new ArgumentNullException(nameof(value));
}
```

键校验和字符串值校验职责分开，异常原因更加明确。

#### 5. 统一布尔值存储规则

Unity PlayerPrefs 原生只支持 `int`、`float` 和 `string`。GF 使用常量明确布尔值映射：

```csharp
private const int FalseValue = 0;
private const int TrueValue = 1;
```

- `SetBool()` 只写入 `0` 或 `1`。
- `GetBool()` 将非 `0` 值解释为 `true`。
- 默认值同样通过这两个常量转换。

这替代了原代码中散落的数字字面量。

#### 6. 明确删除接口的结果和范围

`RemoveSetting()` 的行为保持为：

- 键不存在时返回 `false`。
- 键存在时调用 `PlayerPrefs.DeleteKey()`，输出日志并返回 `true`。

`RemoveAllSettings()` 调用 `PlayerPrefs.DeleteAll()`，并通过警告日志提示已经删除当前应用的全部 PlayerPrefs 数据。

XML 注释同时明确：

- 全部删除作用于当前应用的 PlayerPrefs。
- 该操作不提供按键恢复能力。
- 调用方需要自行确认删除范围。

#### 7. 明确能力边界

类注释明确说明，该封装不提供：

- 内存缓存。
- 数据加密。
- 数据版本管理。
- 复杂存档能力。

如果后续需要多用户存档、加密、云同步、版本迁移或可替换测试实现，应新增独立的存档/设置服务接口，而不是继续扩大这个 PlayerPrefs 静态封装。

#### 8. 按数据职责组织代码

当前代码使用 `region` 划分为：

- `存储管理`
- `布尔值`
- `整数`
- `浮点数`
- `字符串`
- `参数检查`

### 静态化设计取舍

`PlayerPrefsSetting` 适合静态化，原因是：

- 没有实例状态。
- 没有初始化和释放逻辑。
- 没有缓存。
- 底层 PlayerPrefs 本身就是静态 API。
- 单例只会增加 `.Instance` 调用噪声。

同一轮也评估了 `Logger` 是否应改成静态类。当前没有修改 Logger，原因是它已经存在运行状态 `IsEnabled`，未来还可能扩展日志等级、文件输出、网络上报或可替换日志后端。当前继续保留单例更利于后续演进，且单例锁开销相对于 Unity 日志输出很小。

### 使用示例

```csharp
PlayerPrefsSetting.SetBool("MusicEnabled", true);
PlayerPrefsSetting.SetFloat("MusicVolume", 0.8f);

bool enabled = PlayerPrefsSetting.GetBool("MusicEnabled", true);
float volume = PlayerPrefsSetting.GetFloat("MusicVolume", 1f);

PlayerPrefsSetting.Save();
```

### 兼容性说明

旧调用：

```csharp
PlayerPrefsSettingMgr.Instance.SetBool("MusicEnabled", true);
bool saved = PlayerPrefsSettingMgr.Instance.Save();
```

需要改为：

```csharp
PlayerPrefsSetting.SetBool("MusicEnabled", true);
PlayerPrefsSetting.Save();
```

迁移后还需要在未来的 `GameMgr` 中删除旧生命周期调用：

```csharp
PlayerPrefsSettingMgr.Instance.OnInit();
PlayerPrefsSettingMgr.Clear();
```

这些调用对静态工具已没有意义。

## 5. EventSystem

### 相关文件

- `Assets/C#Scripts/Framework/EventSystem/EventCenter.cs`
- `Assets/C#Scripts/Framework/EventSystem/EventDefine.cs`

### 模块职责

EventSystem 提供进程内的同步事件注册、移除和触发能力，支持：

- 无参数事件。
- 1～3 个参数的事件。
- 普通监听。
- 一次性监听。
- 按事件移除全部监听。
- 清空事件中心。
- 使用枚举隔离事件名称。

事件监听回调始终在调用 `EventTrigger()` 的线程执行。事件中心不会自动把回调切换到 Unity 主线程；需要访问 Unity API 的事件必须由主线程触发。

### 已完成改动

#### 1. 迁入独立命名空间

GF 中 EventSystem 使用：

```csharp
namespace GameFramework.EventSystem
```

`EventCenter`、`E_EventName` 以及后续事件相关公共类型均应放在该命名空间中。

#### 2. 使用 System.Action 替代 UnityAction

NGF 使用 `UnityEngine.Events.UnityAction` 保存监听器。GF 改为使用：

```csharp
Action
Action<T>
Action<T1, T2>
Action<T1, T2, T3>
```

事件中心本身不需要 UnityEvent 的序列化或 Inspector 能力，因此使用 `System.Action` 可以减少对 `UnityEngine.Events` 的非必要依赖。

旧代码如果把回调保存在 `UnityAction` 变量中，需要改成 `System.Action`，或者直接传递方法组和 Lambda。

#### 3. 保留全局事件定义文件

全局跨模块事件统一注册在：

```text
Assets/C#Scripts/Framework/EventSystem/EventDefine.cs
```

当前已注册：

```csharp
public enum E_EventName
{
    OnLanguageChanged
}
```

`E_EventName` 用于需要跨模块通信、应由多个系统共同识别的事件。只在单个模块内部使用的事件仍可以由模块定义自己的枚举，因为 `EventCenter` 的事件键参数类型为 `Enum`。

不同枚举类型即使成员名称和底层数值相同，也会被视为不同事件键。需要避免的是同一个枚举内部给两个成员设置相同数值，因为它们会被视为同一个事件。

#### 4. 一个事件键只允许一种参数签名

GF 为每个事件键保存唯一的委托类型。例如：

```csharp
EventCenter.Instance.AddEventListener(
    E_EventName.OnLanguageChanged,
    OnLanguageChanged);
```

注册后，该事件对应的签名是 `Action`。如果使用带参数方式触发同一个事件：

```csharp
EventCenter.Instance.EventTrigger(
    E_EventName.OnLanguageChanged,
    language);
```

事件中心会抛出 `InvalidOperationException`：

- 原无参监听不会被调用。
- 原监听不会因为本次错误触发而被移除。
- 改回无参方式触发后，原监听仍可正常执行。

这种严格签名策略可以尽早发现事件注册端与触发端的契约不一致，替代 NGF 中强制转换失败后产生的空引用异常。

如果事件需要传递语言值，应在第一次注册时统一使用相同签名：

```csharp
EventCenter.Instance.AddEventListener<SystemLanguage>(
    E_EventName.OnLanguageChanged,
    OnLanguageChanged);

EventCenter.Instance.EventTrigger(
    E_EventName.OnLanguageChanged,
    targetLanguage);
```

同一个事件不能同时拥有无参监听和带参监听。确实需要两种通知语义时，应注册两个不同的事件名称。

#### 5. 修正一次性监听的重入行为

NGF 在一次性监听执行完成后才把委托设为 `null`。如果一次性回调内部再次触发同一事件，该监听可能被重复调用。

GF 在调用回调前取出并清除一次性监听：

- 当前触发仍会执行一次性监听。
- 回调内部再次触发相同事件时，不会再次执行该一次性监听。
- 事件槽中已经没有任何监听器时，会自动从字典删除。

#### 6. 增加明确的签名冲突检查

NGF 直接使用 `as EventInfo<T>` 转换事件数据。注册和触发参数类型不一致时，转换结果可能为 `null`，随后产生难以定位的 `NullReferenceException`。

GF 会比较事件槽实际保存的委托类型，并在冲突时抛出包含以下信息的 `InvalidOperationException`：

- 事件枚举类型。
- 事件成员名称。
- 已注册的委托类型。
- 本次尝试使用的委托类型。

#### 7. 支持触发期间安全修改监听器

GF 在锁内取得普通监听和一次性监听的调用快照，在锁外执行回调：

- 注册、移除、清理和获取触发快照均受同步锁保护。
- 回调执行期间不会占用事件中心的内部锁。
- 回调可以继续注册或移除事件，不会在遍历 Dictionary 时导致集合修改异常。
- 触发开始后才移除的监听器仍可能出现在本次已经取得的快照中，从下一次触发开始生效。

#### 8. 增加清理接口

当前提供：

```csharp
RemoveAllEventListeners(eventName)
ClearAllEventListeners()
EventCount
```

同时，`EventCenter` 覆盖 `Singleton<T>.OnRelease()`。调用：

```csharp
EventCenter.Clear();
```

会先清空全部事件监听，再释放单例引用。

#### 9. 收紧内部类型可见性

NGF 将 `IEventInfo` 和不同参数数量的 `EventInfo` 类型公开在全局命名空间中。

GF 将事件槽实现改为 `EventCenter` 内部的私有泛型类型：

```csharp
EventSlot<TDelegate>
```

调用方只能通过 EventCenter 的公共 API 操作事件，不能直接修改内部委托字段。

### 使用示例

无参全局事件：

```csharp
using GameFramework.EventSystem;

EventCenter.Instance.AddEventListener(
    E_EventName.OnLanguageChanged,
    OnLanguageChanged);

EventCenter.Instance.EventTrigger(
    E_EventName.OnLanguageChanged);

EventCenter.Instance.RemoveEventListener(
    E_EventName.OnLanguageChanged,
    OnLanguageChanged);
```

一次性监听：

```csharp
EventCenter.Instance.AddOnceEventListener(
    E_EventName.OnLanguageChanged,
    OnLanguageChangedOnce);
```

带参数事件：

```csharp
EventCenter.Instance.AddEventListener<SystemLanguage>(
    E_EventName.OnLanguageChanged,
    OnLanguageChanged);

EventCenter.Instance.EventTrigger(
    E_EventName.OnLanguageChanged,
    targetLanguage);
```

以上两种 `OnLanguageChanged` 签名只能选择一种作为实际项目契约，不能同时注册。

### 兼容性说明

- 旧的 `UnityAction` 参数需要改为 `System.Action`、方法组或 Lambda。
- EventSystem 类型需要引入 `GameFramework.EventSystem` 命名空间。
- NGF 的事件成员 `OnLanguageChange` 在 GF 中统一更名为 `OnLanguageChanged`。
- 同一个事件键混用不同参数签名时，现在会主动抛出 `InvalidOperationException`。
- 事件中心支持多线程注册和触发，但不会把 Unity API 回调调度到主线程。

### 当前迁移范围

本阶段只迁移 UI 基础运行环境和面板管理闭环：

- 代码构建常驻 `UICanvas`。
- 统一配置 `CanvasScaler` 分辨率适配。
- 创建或复用唯一的 Unity UI `EventSystem`。
- 创建四个固定 UI 层级。
- 从 `Resources/Prefabs/UI/Panels` 加载面板。
- 打开、关闭、查询、置顶和批量关闭面板。
- 提供 `BasePanel.OnInitialize`、`BasePanel.OnOpen`、`BasePanel.OnClose` 生命周期。
- 通过直接对象引用维护 UI 字段绑定，并生成类型安全的初始化代码。

以下 NGF 逻辑没有迁移：

- 黑色背景遮罩。
- `BasePanelFullScreen`、`BasePanelWindow`。
- 面板内部 `BaseLayer` 切换。
- 引导目标组件字典。
- `SetOpenParam(object)`。
- 通过 GameObject 名称管理面板。

### UI 运行环境

`UIViewMgr` 继承 `SingletonMono<UIViewMgr>`，由启动流程显式调用：

```csharp
UIViewMgr.Instance.OnInit();
```

初始化是幂等的，完成后生成：

```text
UIViewMgr
├── UICanvas
│   ├── BackgroundLayer
│   ├── NormalLayer
│   ├── PopupLayer
│   └── OverlayLayer
└── UIEventSystem
```

Canvas 使用 `ScreenSpaceOverlay`，参考分辨率为 `1920 × 1080`，缩放模式为 `ScaleWithScreenSize`，宽高匹配系数为 `0.5`。所有层级和面板根节点均拉伸到父节点全尺寸。

以上对象名称、资源根路径、Canvas 参数、Unity UI Layer 名称和 UI 层级顺序统一定义在 `UIDefines` 中，`UIViewMgr` 不再持有对应硬编码配置。

GF 当前没有安装新 Input System，因此新建事件系统时使用 `StandaloneInputModule`。场景已有唯一 EventSystem 时会复用并迁移到常驻 UI 根节点；存在多个 EventSystem 时初始化会抛出明确异常。

### UI 分层

当前层级由低到高依次为：

```csharp
Background
Normal
Popup
Overlay
```

层级节点保存在 `Dictionary<UILayer, RectTransform>` 中，不再使用 Canvas 子节点下标。面板只会在自己的层级内通过兄弟节点顺序置顶，不会改变不同层级之间的固定渲染关系。

### 面板管理

`UIViewMgr` 使用面板具体类型作为唯一键，同一种面板类型最多存在一个打开实例：

```csharp
T OpenPanel<T>()
bool ClosePanel<T>()
bool IsPanelOpen<T>()
bool TryGetPanel<T>(out T panel)
bool BringToFront<T>()
void CloseAllPanels()
```

面板已经打开时，再次调用 `OpenPanel<T>()` 只会在所属层级中将其置顶，不会再次实例化，也不会重复调用 `OnOpen`。

关闭面板使用实例和具体类型校验，不依赖预制体名称或实例名称。管理器会先移除登记，再调用 `OnClose`，最后销毁对象，因此关闭回调可以安全地重新打开同类型面板。

### BasePanel 职责

`BasePanel` 只负责：

- 通过序列化字段声明 `UILayer`。
- 保存所属 `UIViewMgr`。
- 暴露 `IsInitialized` 和 `IsOpen` 状态。
- 通过 `Close()` 请求管理器关闭自身。
- 自动调用生成代码重写的 `OnBindUI`，并向派生面板提供一次性的 `OnInitialize` 以及可重复的 `OnOpen`、`OnClose` 生命周期。

面板预制体根节点必须挂载具体 `BasePanel` 派生组件和 `RectTransform`。窗口的实际尺寸应由全屏根节点下的内容节点控制。

### UIElementBuilder

NGF 使用 GameObject、字段名、类型字符串和访问权限四个并行列表保存绑定，生成代码再通过列表下标和 `GetComponent<T>()` 获取组件。GF 将其替换为单一的 `List<UIElementBinding>`：

```csharp
UIElementBinding
├── fieldName
├── target
└── generateClickHandler
```

`target` 直接序列化最终的 GameObject 或 Component，不再在运行时依赖数组下标、类型字符串或对象名称。字段名作为稳定键，通过以下接口读取：

```csharp
T Get<T>(string fieldName)
bool TryGet<T>(string fieldName, out T target)
```

首次查询会构建字段名字典；重复字段名、空绑定、失效引用和错误目标类型都会给出明确异常。Builder 不再在初始化后销毁，因此后续代码仍可安全查询绑定，面板重新打开也不需要重建引用。

自定义 Inspector 使用 Unity 序列化属性和可排序列表，支持：

- 拖入 Builder 根节点或子节点中的 GameObject。
- 在 GameObject 自身及其全部 Component 中选择最终绑定目标。
- 根据 `Btn`、`Img`、`Tmp` 等名称后缀提供首次选择默认值；后缀不参与运行时解析。
- 校验空引用、字段名、重复字段、目标层级和 Button 点击方法配置。
- 拖入对象并识别为 Button 时默认勾选点击方法，之后仍可手动调整。
- 直接在面板脚本同目录生成并维护 `XXXPanel.Binding.cs`，不再复制代码。
- 生成所有已勾选 Button 的 partial 点击回调模板，并通过预览窗口一键复制到业务脚本。

面板主类只需要声明为 `partial`：

```csharp
public partial class LoginPanel : BasePanel
{
    partial void OnCloseBtnClick()
    {
        Close();
    }
}
```

生成的 `LoginPanel.Binding.cs` 使用目标对象的真实完整类型，并重写 `OnBindUI()`：

```csharp
// <auto-generated by UIElementBuilder>
public partial class LoginPanel
{
    private global::UnityEngine.UI.Button closeBtn;

    protected override void OnBindUI()
    {
        base.OnBindUI();
        global::GameFramework.UI.UIElementBuilder builder = GetComponent<global::GameFramework.UI.UIElementBuilder>();
        closeBtn = builder.Get<global::UnityEngine.UI.Button>(nameof(closeBtn));
        closeBtn.onClick.AddListener(HandleOnCloseBtnClick);
    }

    private void HandleOnCloseBtnClick()
    {
        OnCloseBtnClick();
    }

    partial void OnCloseBtnClick();
}
```

`BasePanel.Initialize()` 会先执行一次 `OnBindUI()`，再执行 `OnInitialize()`，因此业务初始化可以直接使用已绑定字段。按钮通过生成的桥接方法调用 partial 方法；业务逻辑只写在主面板文件，重新生成 Binding 文件不会覆盖业务实现。没有实现的 partial 点击方法会被编译器移除，仍可正常编译。

Inspector 的“生成点击回调模板”会输出由 `#region 点击回调` 包裹的全部空 partial 方法实现。开发者复制到业务 partial class 内部后，只需填写方法体。

生成器只覆盖带有自身自动生成标记的同名 Binding 文件；若目录中已经存在非生成文件，会拒绝覆盖并给出错误。绑定和监听只初始化一次，不会因为同一面板重复打开而重复建立。

为了迁移已有 NGF 预制体，新的 `UIElementBuilder.cs.meta` 沿用原脚本 GUID，并保留四个隐藏旧字段。Inspector 检测到旧数据后可一次性转换为直接引用；只有全部旧类型都能解析时才会清空旧列表。旧的 public/protected 选项不再保留，生成字段统一为 private。

### 当前限制

- 面板资源仍使用同步 `Resources.Load`。
- 关闭面板后直接销毁，尚未实现缓存池。
- 尚未提供强类型打开参数。
- 尚未处理安全区、打开关闭动画和异步加载取消。
- 业务场景应逐步停止自行创建 EventSystem，最终由 UI 框架统一持有唯一实例。
- 面板主类必须声明为 `partial`；生成器不会自动修改业务脚本的类声明。

## 7. StateMachine

### 相关文件

- `Assets/C#Scripts/Framework/StateMachine/State.cs`
- `Assets/C#Scripts/Framework/StateMachine/StateMachine.cs`
- `Assets/C#Scripts/Tests/Editor/StateMachineTests.cs`

### 模块职责

StateMachine 是不依赖 Unity 生命周期的同步有限状态机，负责：

- 使用枚举标识和注册状态。
- 保存所有状态共享的业务上下文。
- 启动、切换、显式重进和停止状态机。
- 由业务代码主动调用 `Tick(float deltaTime)` 驱动当前状态。
- 对状态生命周期内发起的重入切换进行排队。
- 限制单次操作的连续切换次数，防止循环切换。

### 类型结构

NGF 使用 `Dictionary<int, BaseState<T>>`，业务代码需要把枚举强制转换为 `int`，且 `BaseState.stateId` 从未赋值。GF 改为：

```csharp
State<TContext>
StateMachine<TStateId, TContext> where TStateId : struct, Enum
```

状态 ID 只保存在状态机字典中，不再由状态对象重复保存。状态实例注册时由状态机注入只读业务上下文，同一个实例不能重复注册或跨状态机复用。

### 生命周期

`State<TContext>` 向派生状态提供：

```csharp
protected TContext Context { get; }
protected virtual void OnEnter()
protected virtual void OnTick(float deltaTime)
protected virtual void OnExit()
```

外部不能绕过状态机直接调用生命周期。状态预先注册并复用，正常切换不会创建新状态实例。

状态机公开接口为：

```csharp
void AddState(TStateId stateId, State<TContext> state)
bool ContainsState(TStateId stateId)
void Start(TStateId initialStateId)
bool ChangeState(TStateId targetStateId)
void RestartCurrentState()
void Tick(float deltaTime)
bool Stop()
```

`ChangeState()` 切换到当前状态时返回 `false`，不重复执行生命周期；确实需要重新进入时调用 `RestartCurrentState()`。`Stop()` 会执行当前状态的 `OnExit()` 并清空运行状态。

### 重入切换

状态允许在 `OnEnter()` 或 `OnExit()` 中请求下一次切换。请求不会递归破坏当前切换，而是在当前回调结束后于同一次操作中按顺序处理：

```text
First.OnEnter
First.OnExit
Second.OnEnter
Second.OnExit
Third.OnEnter
```

单次操作默认最多连续处理 32 次切换，也可以通过构造参数调整。超过限制会清空待处理请求并抛出 `InvalidOperationException`，当前已经成功进入的状态保持有效。`Stop()` 是当前切换批次的终止请求，执行后丢弃其余待处理切换，避免状态机被意外重新启动。

### 异常语义

- 注册空状态、重复 ID 或复用状态实例时抛出明确异常。
- 启动或切换到未注册状态时抛出 `KeyNotFoundException`。
- 未启动时切换、重进或重复启动时抛出 `InvalidOperationException`。
- `OnExit()` 抛出异常时保留原当前状态，并解除切换保护。
- `OnEnter()` 抛出异常时清空未完整进入的当前状态，并解除切换保护。
- 核心状态机不依赖 `Logger`，由业务调用层决定如何记录或处理异常。

### 使用示例

```csharp
private enum GuideStateId
{
    Init,
    Execute,
    Finish
}

private sealed class InitState : State<GuideContext>
{
    protected override void OnEnter()
    {
        Context.Initialize();
    }
}

StateMachine<GuideStateId, GuideContext> stateMachine = new(context);
stateMachine.AddState(GuideStateId.Init, new InitState());
stateMachine.Start(GuideStateId.Init);
```

该模块默认由 Unity 主线程使用，不提供线程同步、反射注册、分层状态、异步状态或 MonoBehaviour 自动驱动。

### 验证范围

编辑器测试覆盖：

- 完整生命周期和 `Tick` 参数。
- 注册、启动和未注册状态校验。
- 同状态忽略与显式重进。
- `Enter` 中连续重入切换。
- 循环切换次数保护。
- `Stop` 终止后续排队切换。
- `Enter` 和 `Exit` 异常后的状态一致性及可恢复性。
